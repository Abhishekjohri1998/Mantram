# 2026-06-10

## Storyboard Avatar & Character Reference Fix

### Problem
When creating a storyboard or animating a video, if the user uploads a custom character/avatar from the system, it was not being processed or reflected in the generated storyboards and videos. This is because the raw S3 URLs are private, causing 403 Forbidden errors when external services (multimodal LLMs, Atlas Cloud APIs) attempt to retrieve them.

### Solution & Changes
- **agentUtils.js:** Dynamically sign S3 URLs inside `callMultimodalAgent` using `getSignedUrlIfNeeded` before executing LLM vision requests.
- **storyboardLongForm.js:** Signed S3 URLs for `imageUrl`, `firstFrameUrl`, `characterRefSheetUrl`, `avatarUrls`, and `refImageUrls` on-the-fly inside the background compiler.
- **video-studio.js:** Added fallback in `/storyboard/regenerate-segment` to fall back to individual avatar URLs and sign all references on-the-fly.

### Verification
- Created unit test script `backend/scratch/test-avatar-signing.js` which verifies S3 URL signing, `callMultimodalAgent` intercepting, and regenerate-segment fallback references logic. All tests passed.
