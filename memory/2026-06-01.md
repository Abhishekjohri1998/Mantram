# Daily Log: 2026-06-01

## Context & Task
Resolved the database connection failure issue reported by the user (`Database is temporarily unavailable`). 

## Diagnostics & Solution
1. **Diagnosis**: The server log showed repeated connection timeouts and refusals:
   `connect ECONNREFUSED 159.41.196.103:27017`
   This is because the current workspace public IP address (`45.127.44.72`) is not whitelisted in the MongoDB Atlas console (Network Access).
2. **Crash Loop Fix**:
   - In `db.js`, if the MongoDB connection failed in `production` mode, the process exited (`process.exit(1)`). Under local `node --watch` execution, this caused the dev server to crash permanently and wait for manual file changes to restart.
   - Added a watch-mode detector `process.execArgv.some(arg => arg.startsWith('--watch'))` so the server handles connection failures gracefully in local development without exiting.
3. **Connection Storm Fix**:
   - Guarded the connection logic using `mongoose.connection.readyState` checks to prevent duplicate connect requests and recursive disconnect/reconnect loops that exhaust database sockets.
