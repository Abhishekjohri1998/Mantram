# Memory — 2026-06-12

## Context & Focus
- Fixed "Prompt Enhance" in Creative Studio's AI Create.
- Resolved the TikTok publishing failure when publishing images or carousels.

## Decisions & Insights
- Resolved a critical bug where the prompt enhance feature returned an empty string to the client.
- The bug was caused by the MCoT Visual Grounding block being joined with `\n` in `nodes.js` instead of a double newline `\n\n`. When `creatives.js` attempted to find `\n\n` to strip the metadata, it returned `-1` and fallback-sliced the prompt starting at index `0`, yielding `""` (empty string).
- Fixed by appending `+ '\n\n'` to the visual grounding prefix in `nodes.js`, ensuring proper separation, and rewriting the stripping logic in `creatives.js` to dynamically filter grounding lines as a fallback.
- Successfully verified and tested with the `user@mantram.ai` user context.
- Fixed the TikTok publish failure (`TikTok requires a video URL`) when publishing non-video assets (single image or carousel) from Creative Studio:
  - Added support for the TikTok Content Posting API v2 Photo/Content Init endpoint (`/v2/post/publish/content/init/` with `media_type: "PHOTO"` and `post_mode: "DIRECT_POST"`) in `backend/services/tiktokService.js` under the new `publishPhotosToTikTok` service function.
  - Updated both `backend/routes/social.js` and `backend/services/scheduledPostPublisher.js` to dynamically choose between `publishVideoToTikTok` (if `videoUrl` is present) and `publishPhotosToTikTok` (if `imageUrl` / `imageUrls` are present) for single-post and carousel-post workflows.
  - Corrected `publishVideoToTikTok`'s payload `privacy_level` from `PUBLIC` (invalid value) to the valid enum value `PUBLIC_TO_EVERYONE`.
  - Verified account validity using `creator_info/query/` which returned 200 OK.
- Fixed the issue in the frontend `PublishModal` where a "Published! 🎉" success message was unconditionally shown at the top of the modal even when the publication actually failed (or partially succeeded). Added dynamic header elements (Success, Failure, Partial Success) with distinct icons and red/yellow warning styles, and display of specific backend errors under each account item.
- All fixes have been pushed to the `staging` branch.
