- **GPT Image 2 & DALL-E 3 Decoupling**: Completely decoupled `gpt-image-2` from `dall-e-3` across the backend. Removed leftover comments, size mapping restrictions, and prompt references to DALL-E in `agentCommand.js`, `nexus.js`, and `laozhangClient.js`. Reconfirmed that DALL-E 3 is fully blocked/deprecated and that requests for `gpt-image-2` route directly to the model endpoint with no remapping or fallbacks.
- Removed unused imports of `qAdsPresets` constants from `storyboardDirector.js`.
- **Fixed Reference Image Slot Mapping for gpt-image-2**: Restrained the product image reference collection inside `generateWithGptImage2` to only pass the first (hero) product image. Passing multiple product images (e.g. 4 different angles) was pushing the avatar/presenter reference out of its expected slot on the LaoZhang gateway edits endpoint, causing the generator to ignore the avatar face and mix it with product features.

Ensured S3 URLs are signed via `getSignedUrlIfNeeded` before fetching, and added eager downloading of the avatar URL to a buffer when passed as a URL.
- Cleaned up a duplicate `totalDuration` field in the Mongoose schema `VideoProject.js`.
- Confirmed correct nesting of DOM nodes in the review container of `Storyboard.jsx`.
- Verified MongoDB `.lean()` usage properly extracts `Mixed` fields without Mongoose wrapping.
- **Reference Image Scrambling Fix (`atlasClient.js`)**: Corrected reference image merging order (`[...rawImageUrls, ...rawRefImages]`) in `submitAtlasCloudPayload` for `reference-to-video` model calls. Previously, putting `rawImageUrls` (first frame) at the end caused Atlas to misalign the `@image1`/`@image2` tags (e.g. using the storyboard poster as the first frame product, and the logo as the avatar face).
- **Avatar Restore on Reuse (`video-studio.js`)**: Added `project.input.avatarUrl` S3 signature generation to `signVideoProjectAssets` so that reused projects properly restore the presenter avatar in the React state.
